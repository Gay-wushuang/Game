- # Battle UI Graybox v1.0 — Layout Frozen

  本文定义的战斗 UI 灰盒布局自此冻结。后续只允许替换正式美术、调整视觉样式和修复交互缺陷；未经新的布局规格确认，不再变更三区结构、战位尺寸、手牌区域或核心信息层级。

  ## 《Battle UI 最终灰盒收口方案（删减版）》

  ## 0. 收口目标

  最终灰盒只保留四类东西：

  > **战场主体 + 必要资源 + 当前上下文 + 唯一主操作**

  不再追求“每个功能都有一个常驻按钮”。

  设计原则定死：

  - **敌方永远在上，我方永远在下**
  - **场景画面优先于面板面积**
  - **状态信息优先于说明文字**
  - **上下文交互优先于常驻按钮**
  - **纠错操作不占主视觉位置**
  - **一个信息只出现一次**
  - **灰盒阶段不为占位内容做精装修**

  ------

  # 1. 最终整体排盘

  建议冻结成：

  ```text
  ┌───────────────────────────────────────────────────────────────┐
  │ 第1回合              当前操作提示                  日志   设置 │
  ├───────────────┬───────────────────────────────┬───────────────┤
  │ 敌方 ↑        │                               │ 敌方指挥官    │
  │   VS          │         敌方 5 战位            │ 敌方手牌 ●●●● │
  │ 我方 ↓        │                               │               │
  │               │                               │               │
  │               │                               │               │
  │   场景背景    │                               │               │
  │   完全露出    │         我方 5 战位            │ 我方指挥官    │
  │               │                               │ 状态          │
  │               ├───────────────────────────────┤               │
  │               │            手牌               │               │
  │ ♛4   ▣26      │                               │     ◉         │
  │ ▨0   ◇30      │                               │   AP 2/3      │
  │               │                               │   结束回合     │
  └───────────────┴───────────────────────────────┴───────────────┘
  ```

  核心变化：

  **左侧不再是一根实心 Sidebar。**

  它只是两个 HUD 锚点：

  ```text
  左上：阵营方向
  左下：资源 Dock
  中间：完全露背景
  ```

  右侧也不再承担“三个大按钮”，只剩：

  ```text
  信息区
  +
  上下文动作
  +
  结束回合主控件
  ```

  ------

  # 2. 左侧：最终改成 HUD Rail

  ## 左上阵营 HUD

  只保留：

  ```text
  ◆ 敌方 ↑
  
     VS
  
  ◇ 我方 ↓
  ```

  建议高度：

  ```text
  110~128 px
  ```

  不需要 `188px`。

  而且：

  ```text
  中央战场：上敌下我
  右栏：上敌下我
  左栏：上敌下我
  ```

  三处彻底统一。

  ------

  ## 左下资源 Dock

  保持你决定的**纯符号方案**。

  最终：

  ```text
  ┌───────┬───────┐
  │ ♛  4  │ ▣ 26  │
  ├───────┼───────┤
  │ ▨  0  │ ◇ 30  │
  └───────┴───────┘
  ```

  四个含义继续靠：

  - 新手教程首次说明
  - Hover Tooltip
  - 后续玩家记忆

  不要常驻文字。

  ### 尺寸

  每格建议：

  ```text
  56~64 px 高
  72~84 px 宽
  ```

  整个 2×2 Dock 不应超过大约：

  ```text
  170 × 120 px
  ```

  ### 视觉

  默认：

  ```text
  图标 + 数字
  弱背景
  ```

  Hover：

  ```text
  背景稍亮
  Tooltip 出现
  ```

  不要再像四个菜单按钮。

  ------

  ## 左侧中间

  **什么都不放。**

  而且最关键：

  > `LeftSidebar` 本身不要再有明显实心 Panel 背景。

  背景图直接延伸进去。

  这样这部分不是：

  > “空 UI”

  而是：

  > **负空间 / 环境展示区**

  以后场景背景、美术光效、天气、环境粒子都可以在这里显示。

  ------

  # 3. 顶部 HUD

  顶部最终只保留：

  ```text
  左：训练场 · 第1回合
  中：当前操作提示
  右：战斗日志 / 设置
  ```

  例如：

  ```text
  训练场 · 第1回合
  
              选择英雄并部署到我方空位
  
                                        战斗日志   设置
  ```

  ## 删除

  顶部独立：

  ```text
  AP 5/5
  ```

  因为 AP 后面会并入“结束回合”。

  这样能再减少一次信息重复。

  ------

  # 4. AP + 结束回合合并

  这是我最建议你做的最后一个“大改动”。

  删除现在普通长方形：

  ```text
  结束回合
  ```

  改成一个**圆形 / 环形主控件**。

  例如：

  ```text
        ╭───────╮
       ╱   2/3   ╲
      │    AP     │
      │  结束回合  │
       ╲         ╱
        ╰───────╯
  ```

  ## 控件表达两件事

  ### 中央数字

  ```text
  2 / 3
  ```

  表示剩余 AP。

  ### 外圈

  表示 AP 比例：

  ```text
  3 AP → 满环
  2 AP → 2/3 环
  1 AP → 1/3 环
  0 AP → 空环
  ```

  正式美术时非常容易做出战斗感。

  ------

  ## 状态规则

  ### AP > 0

  普通状态：

  ```text
  AP 2/3
  结束回合
  ```

  不抢眼。

  ### AP = 0

  控件高亮：

  ```text
  AP 0/3
  结束回合
  ```

  轻微脉冲。

  表达：

  > “你大概率该结束回合了。”

  ### 当前没有任何合法行动

  即便 AP > 0，也可以：

  ```text
  结束回合环高亮
  ```

  这比弹提示：

  > “当前没有可执行操作”

  信息熵低很多。

  ------

  # 5. 删除“取消选择”常驻按钮

  彻底删除：

  ```text
  取消选择
  ```

  改成交互规则：

  ```text
  Esc
  右键空白
  再次点击当前对象
  点击其他对象
  ```

  全部都可以取消/切换选择。

  顶部当前提示可以在第一次教程时告诉玩家：

  ```text
  Esc 或右键空白可取消选择
  ```

  之后不再显示。

  ### 原则

  > **纠错动作不应该占一个常驻大按钮。**

  ------

  # 6. 删除“使用英雄技能”常驻按钮

  也不再放：

  ```text
  使用英雄技能
  ```

  这种全局按钮。

  技能是**英雄上下文行为**。

  ------

  ## 推荐交互

  ### 单击我方英雄

  进入：

  ```text
  Selected
  ```

  显示：

  - 选中高亮
  - 可攻击目标
  - 右栏 Hero Detail

  同时在英雄附近出现一个小型上下文动作：

  ```text
  ◉ 技能
  ```

  或者：

  ```text
  [技能]
  ```

  大小只需要约：

  ```text
  72 × 32
  ```

  不是大按钮。

  ------

  ### 技能不可用

  不要显示：

  ```text
  技能（冷却2回合）
  ```

  这种常驻内容。

  直接：

  ```text
  技能图标灰掉
  ```

  Hover：

  ```text
  冷却剩余2回合
  ```

  ------

  ### 如果一个英雄有两个技能

  点：

  ```text
  技能
  ```

  后出现：

  ```text
  技能1
  技能2
  ```

  的小型上下文菜单。

  不要把两个技能永远挂在主 UI 上。

  ------

  # 7. 右栏最终职责

  右栏建议最终只承担：

  > **“我现在正在看什么？”**

  而不是：

  > “所有操作按钮都往这里塞。”

  ------

  ## 默认状态

  显示：

  ```text
  敌方指挥官
  敌方手牌
  
  VS
  
  我方指挥官
  我方状态
  ```

  右栏顺序保持：

  ```text
  敌上
  我下
  ```

  ------

  ## 选中卡牌

  右栏自动切成：

  ```text
  卡牌插画/名字
  
  费用
  类型
  
  规则
  关键词
  ```

  ------

  ## 选中我方英雄

  显示：

  ```text
  英雄
  HP
  攻击
  职业
  星级
  状态
  技能
  被动
  ```

  详细信息都进入这里。

  ------

  ## 选中敌方英雄

  只显示公开信息：

  ```text
  名字
  HP
  攻击（若规则公开）
  职业/星级
  公开状态
  ```

  继续禁止完整技能、隐藏被动、队长能力泄露。

  ------

  # 8. 右栏中间的大 VS

  现在这个：

  ```text
  VS
  ```

  视觉权重仍然偏大。

  建议改成：

  ```text
  ──── VS ────
  ```

  或者干脆：

  ```text
  ────────────
  ```

  只承担分割作用。

  因为：

  ```text
  战场已经告诉玩家谁对谁
  左上也告诉玩家谁对谁
  ```

  第三次强调 `VS` 没太大必要。

  ------

  # 9. 战位再做一次文字减法

  正式灰盒冻结前，我还会再删一点。

  ## 敌方空位

  现在：

  ```text
  空位
  等待敌方部署
  ```

  最终建议只保留：

  ```text
  空位
  ```

  甚至正式美术后可以不写字。

  ------

  ## 我方空位

  现在：

  ```text
  +
  空位
  等待部署
  ```

  最终：

  ```text
  +
  ```

  或者：

  ```text
  +
  空位
  ```

  就够。

  顶部提示已经会告诉：

  > “选择英雄并部署到我方空位。”

  不需要每一个战位再重复五次：

  > 等待部署。

  ------

  # 10. 手牌最终灰盒状态

  手牌结构现在不要再大改。

  只保证六个交互状态：

  | 状态         | 表现             |
  | ------------ | ---------------- |
  | Normal       | 正常卡牌         |
  | Hover        | 上浮、回正、放大 |
  | Selected     | 明显选中         |
  | Unaffordable | 弱化             |
  | Dragging     | 拖拽预览         |
  | Valid Target | 战场目标高亮     |

  卡牌本身仍然：

  ```text
  插画
  +
  极少常驻信息
  ```

  详细规则继续走右栏。

  这是你现在降低信息熵最重要的一步之一。

  ------

  # 11. 敌方手牌继续极简

  建议最终只表现：

  ```text
  ◆ ◆ ◆ ◆
  ```

  甚至：

  ```text
  ◆ ×4
  ```

  而不是显示很小的真实卡背。

  因为玩家只需要知道：

  > 敌人有几张牌。

  不需要辨认每张卡背。

  ------

  # 12. 战斗 HUD 不再增加常驻元素

  灰盒冻结之后，以下东西禁止再加入主界面：

  ```text
  常驻攻击按钮
  常驻技能按钮
  取消选择按钮
  额外 AP 显示
  职业完整文字
  EXP
  完整卡牌规则
  操作教程
  完整敌方技能
  大面积战斗说明
  ```

  新功能优先考虑：

  ```text
  图标
  状态
  Hover
  右栏
  上下文动作
  顶部短提示
  ```

  而不是加新面板。

  ------

  # 13. 最终信息层级

  整个界面应该形成非常明确的 5 层：

  ### L1 战场

  最重要。

  ```text
  人物
  目标
  攻击
  技能
  状态变化
  ```

  ------

  ### L2 手牌

  玩家当前可以做什么。

  ------

  ### L3 回合环

  ```text
  AP
  结束回合
  ```

  唯一常驻主操作。

  ------

  ### L4 上下文详情

  右栏。

  用户主动看才获得详细信息。

  ------

  ### L5 辅助 HUD

  左上阵营、左下资源、日志、设置。

  视觉权重最低。

  # 16. 灰盒冻结标准

  当下面这些全部满足，就不要再动大布局：

  > **中央战场是视觉主体；左侧只剩两个悬浮 HUD；右栏只负责上下文信息；底部没有一排固定操作按钮；全局唯一主动作是“AP + 结束回合”回合环；所有其他操作由卡牌、英雄和目标自身产生。**

  到这个程度以后，就可以正式把 Battle UI 标成：

  # `Battle UI Graybox v1.0 — Layout Frozen`

  之后再觉得“这里空”“那里单调”，**优先通过背景、美术、粒子、人物动画、战位皮肤解决，而不是继续加 UI。**

  这会是我目前最推荐的最终收口版本。
