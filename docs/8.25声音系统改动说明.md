# 8.25 声音系统改动说明

> 交接说明：本次改动涉及的音频问题与新增的战斗 BGM 状态机。
> 涉及文件：`scripts/audio/BattleBgm.cs`（新增）、`scripts/audio/AudioManager.cs`、`scripts/ui/SceneRouter.cs`、`scripts/TrainingArena.cs`、`scripts/data/CardCatalog.cs`。

## 一、修的 Bug

### 1. 音乐播放不响（重点）
- 现象：主菜单 / 战斗 BGM 全部无声（headless 测试正常，真实设备无声）。
- 根因：`AudioManager.LoadLoop` 给 wav 副本设 `LoopMode = Forward` 后未设 `LoopEnd`（默认 0），Godot 循环区间非法 → 播放器初始化失败、直接停播；headless 的 Dummy 驱动会"假装播放"，掩盖了问题。
- 修复：显式 `LoopEnd = (int)(GetLength() × GetMixRate())` 整段循环。`BattleBgm.LoopCopy` 使用同款逻辑。
- 教训：以后遇到"循环 wav 不响"，先查 `LoopBegin` / `LoopEnd`。

### 2. 上游代码编译失败
- `CardSemanticValidator.cs` / `TrainingArena.cs` 引用 `CardCatalog.V2ExpectedCount`，但 `CardCatalog.cs` 没有该常量（上游仓库本身编译不过）。
- 本改动补 `V2ExpectedCount = 30`（与 `data/generated/cards.generated.json` 当前 30 张一致）。
- ⚠️ 卡牌数据数量变化时需同步该常量。

### 3. 大厅音乐进战斗不停
- 现象：主菜单 BGM 进入战斗后继续响，与战斗 BGM 叠在一起。
- 根因：战斗 BGM 改用独立播放器（BattleBgm）后，没有调用 `AudioManager.StopMusic()`（旧逻辑靠 `PlayBattleMusic` 内部 Stop 顺带停掉大厅音乐）。
- 修复：`TrainingArena._Ready` 进战斗先 `AudioManager.Instance?.StopMusic()`。

## 二、行为调整

| 项目 | 改动 |
| --- | --- |
| 界面切换音效 | 移除漫画转场音效（`SceneRouter.ChangeTo` 不再播 `ComicWhoosh`） |
| 悬停音效 | 全局降低 50%：`PlaySfx` 新增 `volumeScale` 参数（0~1 线性比例，每次播放前显式写 `VolumeDb`，播放器池复用不残留音量），悬停回调传 `0.5` |
| 洗牌音效 | 改为黑幕完全消失（转场完成）后再播：`SceneRouter` 新增 `TransitionCompleted` 事件与 `IsTransitioning`；训练场一次性订阅，就地重开战斗（无转场）则立即播 |
| 战斗 BGM 开局 | 延迟 10 秒改 **2 秒**后开始，主轨 10 秒渐起（音量 0→满） |

## 三、战斗 BGM 三态状态机（`BattleBgm.cs` 新增）

```
状态A 开局：2s 延迟 + 10s 渐起
         → danger_intro(2s) ──无缝直切──> 1循环 danger_loop_a（无限循环）

状态B 满场：场上英雄牌铺满 10 张（5+5）
         → 鼓层 danger_loop_b 从主轨当前进度同步叠入（两轨等长 169s，Seek 对齐，无缝）

状态C 终态：任意英雄死亡 / 任意英雄 3 星（无视 B 是否启动，只触发一次）
         → 旧轨（intro/1循环/2循环）全部淡出 + city_intro 淡入 【4s 交叉淡化，同步升降】
         → city_intro 播完 ──无缝直切──> 3循环 battle_city_loop

战斗结束（胜负）：全部播放器 4s 交叉淡出，完成后由 AudioManager 播胜负 BGM

规则：引子↔循环、叠鼓层 = 无缝直切；只有整轨替换（进3、战斗结束）才有 4s 交叉淡化
      （新轨淡入与旧轨淡出同时进行，非先降后升）
```

- 播放器：三个独立 `AudioStreamPlayer`（BgmMain / BgmLayer / BgmClimax），走 Music 总线；`AudioManager.cs` 未动。
- 触发点（`TrainingArena.cs`）：
  - 满场：`RefreshAll` 内判断存活英雄数 ≥ 10（激活后幂等）
  - 英雄死亡：死亡结算处，仅限 `HeroDefinition`（怪物死亡不触发）
  - 3 星：`ApplyStarChoice` 升星到 3 的瞬间
  - 胜负：结算分支改走 `FadeOutAnd`（淡出完再播）
