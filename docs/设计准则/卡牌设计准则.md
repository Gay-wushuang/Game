# 卡牌设计准则

> 状态：正式采用。基线：commit `77e1252`、卡牌 V2。
>
> 本文规定目标语义。`docs/卡牌语义验收矩阵.md` 与 V2 源表负责逐卡验收，`data/generated/cards.generated.json` 是运行时生成数据，C# / Lua 是实现。若四者不一致，应作为缺陷修复，不得以当前代码行为反向改写已冻结语义。

## 1. 权威来源与变更流程

权威顺序如下：

1. 用户已确认的规则与本准则；
2. `docs/卡牌类型/主动锦囊v2.xlsx`、`docs/卡牌类型/被动锦囊v2.xlsx`；
3. `docs/卡牌语义验收矩阵.md`；
4. `data/generated/cards.generated.json`；
5. `cards/lua/` 与 C# 实现；
6. Smoke 与回归测试。

修改卡牌时必须同步源表、生成数据、Lua/C#、规则文字和测试。禁止只改卡面文字或只改运行时代码。

当前基线为 30 张锦囊：15 张主动、15 张被动。当前数据统计是基线快照，不是永久卡池上限。

## 2. 卡牌类型与区域

### 2.1 主动锦囊

- 从手牌打出并立即结算。
- 支付 `CardInstance.CurrentCost` 计算出的费用。
- 正常结算后进入弃牌堆；临时复制等明确指定去向的实例除外。
- 目标、合法性和结算不能仅靠 UI 文本判断。

### 2.2 被动锦囊

- 从手牌背面设置到所属阵营的被动战门。
- 设置时支付实际费用；0费来自卡牌定义，不代表被动类型天然免费。
- 每方战门上限为 3 张；同方按槽位从左到右确定结算顺序。
- 触发前不向对手公开牌面；己方可展开查看卡面并查看简介。
- 正常触发后进入弃牌堆；被揭穿或以其他方式离场时按该效果规定处理。
- 被动牌不占英雄槽，也不绑定、保护或指向某个英雄，除非卡牌规则明确创建目标关系。

## 3. 行动力与费用

- 默认行动力：`BattleState.DefaultActionPoints = 5`。
- `FIXED`：使用 `base_cost`。
- `VARIABLE_AP` / `ALL_CURRENT`：X 等于支付前当前玩家剩余的全部 AP。
- `MAX_AP` 仅在未来卡牌明确需要时使用；当前 V2 没有 `MAX_AP` 卡牌。
- 费用修正后的结果不得低于 0。
- 强制下回合 AP 为 0 时，结果固定为 0，优先于 override 与 bonus。
- 否则下回合 AP 为 `max(0, (override ?? DefaultActionPoints) + bonus)`。

当前费用快照：

| 类型 | 0费 | 1费 | 2费 | 3费 | 变量费用 |
|---|---:|---:|---:|---:|---:|
| 主动15张 | 4 | 9 | 1 | 1 | 2 |
| 被动15张 | 13 | 2 | 0 | 0 | 0 |

表中的固定费用与变量费用为交叉维度：两张变量费用牌的 `base_cost` 为0，不应重复推导为固定0费牌。

## 4. 手牌、抽牌和区域

- 全局手牌上限为 8。
- 每个自身回合开始时抽 4 张牌。
- 抽牌堆为空时，将弃牌堆洗回抽牌堆后继续抽取。
- 超过手牌上限的新抽牌直接进入弃牌堆；明确规定放逐的临时牌进入放逐区。
- 自身回合结束时，未使用手牌进入弃牌堆；`PREVENT_DISCARD` 等明确效果可阻止此次自动弃牌。
- 放逐区不参与弃牌堆洗牌与普通检索。

### 4.1 临时复制

- 临时复制是新的 `CardInstance`，不移动原实例的所有权。
- 临时复制使用后立即放逐；回合结束未使用也放逐；永不进入任何弃牌堆。
- 手牌已满时生成的临时复制直接放逐。

### 4.2 “拿来主义”冻结语义

- 敌方原牌从敌方手牌移动到敌方弃牌堆。
- 我方生成一张相同的0费临时复制进入手牌。
- 临时复制使用后立即放逐；本回合未使用则在回合结束时放逐。

## 5. 目标与结算

当前合法 `target_key`：

- `NONE`
- `SELECTED_ALLY`
- `SELECTED_ENEMY`
- `ALL_ENEMIES`
- `SELECT_CARDS`
- `SET_GATE`

新增目标类型必须同步数据解析、合法性检查、玩家 UI、AI 和测试。群体效果优先显式使用 `ALL_ENEMIES`；不得依赖规则文字暗示目标范围。

所有伤害必须标明伤害类型。反伤、伤害转移和持续伤害默认不得再次触发同类反伤或转移，避免递归；需要例外时必须在逐卡语义中明确并设置一次性事件标记。

护盾当前是独立点数池。新增“持续至回合结束”的护盾时必须真正实现到期清除；不得一边写回合结束，一边让其无限保留。

## 6. 被动触发

当前允许的触发键：

`ACTION_POINTS_ZERO`、`AFTER_CARD_RESOLVE`、`ALLY_TURN_ENDED`、`ALLY_TURN_STARTED`、`BEFORE_ATTACK`、`BEFORE_DAMAGE`、`BEFORE_DRAW`、`CARD_TARGETED`、`ENEMY_BATTLE_PHASE_STARTED`、`ENEMY_SLOT_EMPTY`、`HAND_EMPTY`、`HERO_DIED`、`NEXT_ALLY_TURN_STARTED`、`ON_PLACED`、`PASSIVE_SET`。

新增触发键必须同时完成：事件发布、收集规则、结算顺序、AI处理、UI播报、保存恢复和回归测试。

触发时必须按以下流程：合法事件 → 收集候选 → 按槽位排序 → 翻面与播报 → 原子结算 → 移出战门。被抵消或揭穿也必须播报，且不能播放成功结算动画。

## 7. 已冻结的特殊语义

- `X`：支付前当前剩余全部 AP。
- “机关算尽”：X 为当前剩余 AP，下回合 AP 设置为 X+1；不能按 MaxAP=5 解释。
- 不足3张时弃牌：有几张弃几张。
- 冷却牌：冷却期间仍可抽到，但不能打出；不设置独立冷却区。
- 怨恨等按回合移除的层数：在规则指定的阵营回合结束时移除，不能改为受击后移除。
- 全局手牌上限：8。
- “任意一名存活友方”：由效果控制方选择合法目标。
- 阻止自动弃牌：只阻止回合结束的手牌整理，不免除其他弃牌效果。
- 兔子：生成在敌方最左空位；不能攻击、反击或被锦囊指定，但可被敌方角色攻击；拥有独立HP；持续时间按完整敌我轮次计算；一张牌只生成一次。

## 8. 数值、稀有度与设计边界

当前稀有度分布为：1级5张、2级8张、3级11张、4级6张、5级0张。稀有度是内容标签，不自动产生倍率，也没有已实现的携带上限。

新卡不能仅按“每费固定价值”机械换算。至少评估：即时性、目标数量、信息差、触发概率、战门占用、反制窗口、卡差、AP差、区域去向和循环复用。

以下效果必须提供专门的循环与极端状态测试：复制、偷牌、永久费用修改、额外回合/阶段、伤害反射、复活、阻止抽牌、阻止弃牌、区域交换和随机目标。

## 9. 数据与实现规范

- 卡牌ID：小写 ASCII 与下划线，当前采用 `card_<name>`。
- 正式效果使用受限 Lua 入口；战斗状态、合法性、随机数、事件和原子 API 保持在 C#。
- Lua 不得访问文件、OS、SceneTree、Godot单例或场景节点。
- 卡牌正面、背面与插画规格以仓库根目录 `AGENTS.md` 和美术规范为准。
- 正式文字由程序绘制，不烘焙进公共模板。
