# 通用无字卡框设计要点

> 版本：V1.0  
> 适用范围：当前 192×244 px 卡牌视觉系统  
> 适用对象：ACTIVE / PASSIVE 及 ATTACK、CONTROL、SUPPORT、DEFENSE、RESOURCE、SUMMON 等功能牌  
> 核心视觉体系：**角色色 DNA + 黑色实体 + 白色负形 + 动态情绪色**
>
> 本文只规范“无字卡框”本身，不负责人物插画、卡名、AP 数值、星级与规则文本。

---

# 1. 无字卡框的职责

无字卡框不是传统意义上的“完整边框”。

它的职责是：

- 建立卡牌的功能语法；
- 提供稳定的 192×244 外形基准；
- 与人物插画共同完成整张卡的动作构图；
- 通过黑色实体、白色负形和动态情绪色形成高识别度；
- 给 AP、卡名、星级等运行时信息留下明确区域；
- 保持中央人物插画核心可读；
- 让不同卡牌拥有差异，同时保持整套卡牌属于同一个视觉系统。

正式定义：

> **无字卡框 = Card Boundary Composition / 卡牌边界构成**

它不是“框住插画”，而是和插画一起组成画面。

---

# 2. 当前固定规格

## 2.1 尺寸

```text
192 × 244 px
```

当前正式卡牌视觉统一按此尺寸制作。

禁止：

- 非等比缩放；
- 强行套用旧尺寸；
- 先做其他比例再随意拉伸；
- 因为某张插画构图不同而改变整张卡的像素尺寸。

## 2.2 运行时无字卡框必须不包含

正式运行时 Frame 不应烘焙：

- 卡名；
- AP 文本；
- AP 数字；
- 星级；
- 规则说明；
- 动态状态文字；
- 人物插画。

这些应由 Godot 或独立图层负责。

---

# 3. 总体视觉公式

无字卡框统一遵守：

```text
无字卡框
=
黑色实体
+
白色负形
+
动态情绪色
+
非完整边界
+
信息预留区
```

其中：

- **黑色实体**负责重量与结构；
- **白色负形**负责切割、呼吸与方向；
- **动态情绪色**负责本张卡的动作情绪；
- **非完整边界**负责风格化；
- **信息预留区**负责后续 AP、卡名、星级等动态信息。

---

# 4. 第一原则：禁止传统完整卡框

不要做：

```text
完整四边框
+
四角装饰
+
顶部徽章
+
底部矩形标题栏
```

本项目要求：

> **卡牌边界必须是不完整的。**

至少应具有：

- 大面积断口；
- 明确留白；
- 1～2 个主边界方向；
- 不同区域的视觉重量差；
- 局部边界“长入”中央插画区，但不能压住主体。

人的视觉会自动补全卡牌轮廓，不需要真的画完整框。

---

# 5. 第二原则：花纹只能服务“动作句法”

卡框花纹不能只是“好看”。

每一个主要形状都必须能回答：

> **为什么这个形状出现在这里？**

例如：

### ATTACK
因为动作是：

```text
斜切 / 外冲 / 撕裂 / 穿透
```

所以可以出现：

- 长楔；
- 尖角；
- 斜条；
- 断裂；
- 外冲破边。

### SUPPORT
因为动作是：

```text
托举 / 回拢 / 舒展 / 承接
```

所以可以出现：

- 宽托形；
- 回弧；
- 包覆；
- 向上展开的白色负形；
- 柔性流线。

因此：

> **先确定动作，再设计花纹。**

禁止先画一堆装饰，再给它强行解释功能。

---

# 6. 黑色实体设计规则

## 6.1 黑色实体的作用

黑色实体负责：

- 主视觉重量；
- 卡牌边界主体；
- 底部信息承接区；
- AP 区的局部稳定结构；
- 与人物插画产生前后遮挡关系；
- 功能类型的主要几何形。

## 6.2 黑色实体必须“大块化”

应该：

- 面积明确；
- 轮廓清楚；
- 少碎片；
- 有主次；
- 服从动作方向。

不应该：

- 用大量小黑块填满边缘；
- 四周平均分布；
- 形成噪点；
- 为了“复杂”加入没有语义的装饰。

## 6.3 黑色不必机械等于 #000000

视觉上要求“黑色系”，允许极少层次：

```text
主黑
次黑
结构灰黑
```

但缩小后必须仍然首先读成：

> **一个统一的黑色实体。**

---

# 7. 白色负形设计规则

## 7.1 白色不是背景

正式原则：

> **白色既是空白，也是实体。**

白色负形负责：

- 切开黑色实体；
- 给中央插画留下呼吸；
- 强化主动作方向；
- 分离人物与卡框；
- 建立速度、净化、撕裂、回流等感受；
- 形成不完整边界。

## 7.2 不同功能的白色负形要有不同性格

### ATTACK
白色像：

- 被撕开的裂口；
- 高速斩开的空隙；
- 尖锐断面。

### SUPPORT
白色像：

- 被托出来的空间；
- 回流形成的气口；
- 柔和的弧形留白。

### CONTROL
白色像：

- 被两侧结构压缩的窄口；
- 被封锁的通道。

### DEFENSE
白色像：

- 黑色厚块之间稳定的结构缝；
- 不易穿透的狭窄间隙。

### RESOURCE
白色像：

- 流路；
- 分叉；
- 节点之间的通道。

---

# 8. 动态情绪色设计规则

## 8.1 动态情绪色不是“类型固定色”

禁止：

```text
ATTACK = 红
SUPPORT = 绿
CONTROL = 紫
```

正确逻辑：

```text
角色色 DNA
↓
本张卡的动作 / 情绪
↓
选择最合适的情绪色
```

例如：

- 荆铁《暴力手段》：深绯红；
- 神无月《妙手回春》：可使用青绿、淡紫、月白紫等符合角色 DNA 的恢复倾向色。

## 8.2 情绪色必须是“重音”

情绪色应：

- 少；
- 集中；
- 有方向；
- 与主动作轴一致。

不应：

- 四周平均点缀；
- 大面积铺满；
- 变成普通彩色背景；
- 抢走人物与黑白结构的主导地位。

一句话：

> **情绪色是重音，不是底色。**

---

# 9. 卡框中的花纹应该放在哪里

花纹原则上集中在：

## A. 左上信息起势区

用于：

- AP 区附近的视觉起笔；
- 和主边界产生连接；
- 建立第一动作方向。

注意：

- 不要求固定圆形；
- 不要求固定徽章；
- 必须给 AP 留稳定可读空间。

## B. 一侧主花纹区

通常只选：

```text
左侧
或
右侧
```

作为主要生长边。

不要四边同权重。

主花纹区负责：

- 最大黑色实体；
- 主要白色负形；
- 动态情绪色重点；
- 功能语法最强的一段。

## C. 底部信息承接区

底部不是额外贴一个标题框。

应该：

> **由边界自然变厚形成。**

底部暗区必须能够：

- 放置动态卡名；
- 保持足够对比；
- 仍然延续本卡功能句法。

---

# 10. 底部信息区的功能差异

### ATTACK
上沿：

- 撕裂；
- 斜切；
- 外冲；
- 不规则。

### CONTROL
上沿：

- 两侧向内压；
- 中部收口；
- 边界有夹持感。

### SUPPORT
上沿：

- 托举；
- 回拢；
- 柔性上扬；
- 留白舒展。

### DEFENSE
上沿：

- 稳定；
- 厚重；
- 平缓；
- 有“顶住”感。

### RESOURCE
上沿：

- 流路汇入；
- 节点聚集；
- 比较轻薄。

### PASSIVE
总体：

- 更稳定；
- 更附着；
- 更连续；
- 但依然不能完全闭合。

---

# 11. AP 区设计原则

AP 区的外形不固定。

不规定：

```text
必须是圆
必须是方
必须是徽章
```

只规定：

> **稳定、独立、清晰、易读。**

AP 区应与功能句法自然结合。

例如：

### ATTACK
可偏：

- 切角；
- 楔形；
- 撕裂形成的信息口。

### SUPPORT
可偏：

- 柔和弧面；
- 回拢的小型托形；
- 轻量稳定节点。

AP 区应像：

> **卡框动作自然留下的系统区域**

而不是后贴上去的一块 UI。

---

# 12. 星级区域设计原则

无字无星级 Frame 中不直接画星级。

但必须提前预留：

- 位置；
- 对齐基准；
- 视觉空隙。

建议：

- 位于卡名附近或底部中央；
- 不与人物插画主动作重叠；
- 不打断主边界；
- 星级变化后不需要重新绘制卡框。

---

# 13. 中央插画开放区

无字卡框必须优先保护人物插画。

原则：

- 人脸不应被主要卡框花纹遮挡；
- 标志装备至少有一个大形能被读出；
- 主要动作方向不应被卡框反向切断；
- 插画不能被四边装饰包死；
- 卡框和插画应共享动作方向，但不能互相重复所有特效。

核心关系：

```text
边框负责：
“这是什么性质的动作”

插画负责：
“这个角色具体怎么做”
```

---

# 14. 卡框与插画的重叠原则

允许卡框局部覆盖插画。

这种覆盖应该：

- 有明确构图目的；
- 强化纵深；
- 强化动作；
- 保持人物关键识别点。

不要：

- 随机挡脸；
- 把人物大面积埋住；
- 为了“融入”而把卡框花纹铺满角色。

---

# 15. 几何复杂度控制

一张无字卡框建议由：

```text
主边界大形：1
次边界大形：1～2
白色负形：2～4
情绪色主形：1
情绪色辅助形：0～2
小节点：极少
```

组成。

不是死数值，但如果一张卡需要十几二十个独立花纹才能成立，通常说明：

> **设计已经过度复杂。**

---

# 16. “自然化”的正式定义

本项目中的“自然”不是：

- 植物；
- 树叶；
- 藤蔓；
- 花草。

“自然化”指：

> **形状具有合理的生长、运动和受力逻辑。**

例如：

### 攻击
某个尖角是因为攻击方向在那里。

### 回复
某条弧线是因为画面在向角色或目标回流。

### 控制
某个边界收紧是因为空间正在被限制。

因此：

> **形状看起来应该像“动作必然留下的结果”。**

---

# 17. 统一性与差异化

所有卡牌必须共享：

- 192×244；
- 非完整边界；
- 黑色实体；
- 白色负形；
- 动态情绪色；
- 中央人物开放区；
- 底部自然信息区；
- AP 稳定区域；
- 高对比；
- 低噪点；
- 几何动作逻辑。

允许变化：

- 主边界位置；
- 花纹方向；
- 情绪色；
- 黑色面积；
- 白色负形形态；
- AP 外轮廓；
- 底部上沿；
- 插画遮挡方式；
- 角色动作。

目标：

> **同一种语言，不同句子。**

---

# 18. ACTIVE 与 PASSIVE 的卡框区别

## ACTIVE

更强调：

- 动作瞬间；
- 外放；
- 破边；
- 非对称；
- 明确方向。

## PASSIVE

更强调：

- 附着；
- 稳定；
- 连续；
- 等待；
- 条件存在。

即使是攻击型 PASSIVE，也不应该完全复制 ACTIVE 的爆发结构。

---

# 19. 示例：暴力手段

```text
ACTIVE / ATTACK
```

核心句法：

```text
斜切
+
外冲
+
撕裂
+
单方向
```

卡框表现：

- 左上强斜切；
- 右侧/右下形成攻击破边；
- 底部深色情绪区承接卡名；
- 白色像被撞开的裂口；
- 深绯红沿攻击主轴出现。

重点：

> **“撞开”。**

---

# 20. 示例：妙手回春

```text
SUPPORT / HEAL
```

核心句法：

```text
回拢
+
包覆
+
托举
+
净化
+
缓慢上扬
```

卡框表现：

- 左上轻量起势；
- 右侧形成向内回拢的主边界；
- 黑色实体更加稳定；
- 白色负形像被托出的净区；
- 底部形成柔性承接区；
- 情绪色以少量回流弧线 / 节点出现；
- 不使用攻击式大面积撕裂。

重点：

> **“扶起”。**

# 21. Aseprite 推荐图层

```text
CardFrame
│
├─ Guide
│
├─ BlackEntity
│
├─ WhiteNegativeSpace
│
├─ EmotionColor
│
├─ AP_Guide
│
├─ Star_Guide
│
└─ Name_Guide
```

最终导出运行时 Frame 时，只导出：

```text
BlackEntity
+
WhiteNegativeSpace
+
EmotionColor
```

不导出：

- Guide；
- AP；
- 星级；
- 卡名。

---

# 22. 导出规则

正式无字无星级卡框：

```text
PNG
RGBA
192×244
透明背景
```

必须：

- 保留 Alpha；
- 不模糊缩放；
- 最近邻检查；
- 不带 AP；
- 不带卡名；
- 不带星级；
- 不带人物插画。

建议命名：

```text
<card_id>_frame.png
```

例如：

```text
violent_means_frame.png
healing_touch_frame.png
```

---

# 23. Godot 运行时分层建议

```text
CardVisual 192×244
│
├─ Illustration
├─ Frame
├─ Stars
├─ AP
└─ CardName
```

其中：

```text
Frame
=
本规范产出的无字无星级卡框
```

卡名、AP、星级由运行时数据动态显示。

# 24. 最终检查清单

## 构图

- [ ] 是否仍然是非完整边界？
- [ ] 是否只有 1～2 个主边界方向？
- [ ] 主花纹是否服务动作句法？
- [ ] 有没有为了“漂亮”加入无意义装饰？
- [ ] 中央插画区是否足够开放？

## 黑色实体

- [ ] 是否形成明确大形？
- [ ] 是否避免过多小碎片？
- [ ] 是否与功能方向一致？

## 白色负形

- [ ] 是否主动参与构图？
- [ ] 是否不是单纯背景？
- [ ] 是否帮助人物和卡框分离？
- [ ] 是否符合本卡功能气质？

## 动态情绪色

- [ ] 是否来自角色色 DNA 或合理功能情绪？
- [ ] 是否集中而不是平均铺色？
- [ ] 是否跟随主动作轴？
- [ ] 是否没有抢走黑白结构？

## 信息区

- [ ] AP 是否有稳定位置？
- [ ] 卡名区是否自然形成？
- [ ] 星级是否有预留空间？
- [ ] 是否没有把文字烘焙进 Frame？

## 像素落地

- [ ] 是否为 192×244？
- [ ] 是否保留透明通道？
- [ ] 1:1 显示是否清晰？
- [ ] 是否避免高频细节？
- [ ] 是否符合“结构清晰，细节克制”？

# 25. 最终统一原则

本项目的无字卡框必须遵循：

> **不是给插画套一个漂亮框，而是让边界本身成为卡牌动作的一部分。**

统一视觉公式：

# **角色色 DNA + 黑色实体 + 白色负形 + 动态情绪色**

其中：

> **黑色实体负责重量。**  
> **白色负形负责空间。**  
> **动态情绪色负责重音。**  
> **几何句法负责功能。**  
> **非完整边界负责风格。**

最终目标：

> **30 张牌共享同一个视觉系统，却没有 30 张一模一样的框。**

执行口号：

# **结构清晰，细节克制。**
